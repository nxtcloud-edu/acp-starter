# 최종 과제: 내 업무 전용 에이전트 플랫폼

이 레포를 포크해서 **내 업무 하나를 위한 에이전트 플랫폼**을 만들고 발표한다.

Kiro Crew는 모든 사람의 모든 일을 받는 범용 플랫폼이다. 앞에서 Kiro Crew로 내 일을 맡겨 보며 뺄 것, 바꿀 것, 나아지게 할 것을 정했다. 이번에는 그 목록을 바탕으로, 내 업무에 맞게 좁히고 바꾼 플랫폼을 직접 만든다.

만드는 방법은 자유다. 다만 이 레포의 코드를 혼자 다 읽고 고치지 않는다. 내가 쓰는 코딩 에이전트(Kiro CLI, Claude Code, Codex 가운데 하나)에게 레포를 파악하게 하고, 확인시켜 가며 만든다. 방법은 [코딩_에이전트와_일하기.md](코딩_에이전트와_일하기.md)에 있다.

## 받는 것

| 받는 것 | 쓰는 법 |
|---|---|
| 이 레포(`acp-starter`) | 포크해서 내 플랫폼의 출발점으로 쓴다. 로그인, 대화, 허락, 스킬, 일 실행, 결과함이 이미 돈다 |
| Kiro Crew 레포(https://github.com/kirodotdev/KiroCrew) | 참고 자료. 같은 문제를 크게 푼 예로 읽는다. 위치는 [만들_곳.md](../만들_곳.md)에 있다 |
| 과제물(내 수업 레포의 `기록/KiroCrew_경험.md`) | 뺄 것, 바꿀 것, 나아지게 할 것과 그 근거. 계획의 출발점이다 |

## 진행 순서

| 단계 | 할 일 | 남길 곳 |
|---|---|---|
| 1. 포크와 실행 | 이 레포를 내 GitHub 계정으로 포크하고 클론한다. `python dashboard.py`로 열고, 에이전트에 로그인하고, 스킬 두 개를 "해 보기"로 써 본다 | `기록/개발일지.md` |
| 2. 파악 | 내 코딩 에이전트에게 레포를 설명하게 한다. Kiro Crew 레포에서 내가 바꾸고 싶은 기능이 어디 있는지 찾게 한다 | `기록/개발일지.md` |
| 3. 계획 | 과제물의 세 목록을 [만들_곳.md](../만들_곳.md)의 자리에 짝짓고, 만들 순서를 정한다. 이름과 색, 업무 정의부터 정한다 | `계획/계획서.md` |
| 4. 구현 | 계획의 순서대로 만든다. 하나를 만들 때마다 실행해서 확인하고 커밋한다 | 코드, `기록/개발일지.md`, `기록/변경.md` |
| 5. 써 보기 | 내 업무 자료로 실제로 써 본다. 틀리거나 불편한 것을 고친다 | `기록/변경.md` |
| 6. 발표 | 만든 까닭, 만든 것, 바뀐 것을 발표한다 | `발표/` |

계획을 마치면 그 커밋에 `plan` 태그를 단다(`git tag plan && git push origin plan`). 발표에서 `git diff plan..main`으로 계획 뒤에 무엇이 바뀌었는지 보인다.

## 제출

- 포크한 레포를 공개로 두고 계속 커밋하고 푸시한다. 마감은 수업에서 알린다.
- 포크한 레포의 주소를 내 수업 레포의 `안내/최종결과물.md` 아래에 한 줄로 적는다.
- 레포에 남길 것: `계획/계획서.md`, `기록/개발일지.md`, `기록/변경.md`, `발표/`의 발표 자료, 바꾼 코드.

## 살펴볼 것

개수 기준은 없다. 아래를 살펴보며 만든다.

- 내 플랫폼이 어떤 업무를 위한 것인지 이름, 화면, `custom/업무.md`에서 드러나는가.
- 과제물의 뺄 것, 바꿀 것, 나아지게 할 것이 실제로 반영되었는가. 반영하지 않은 것은 그 까닭이 있는가.
- 바꾼 곳마다 실행해서 확인했는가. 확인한 결과가 개발일지에 있는가.
- 코딩 에이전트에게 맡긴 것과 내가 판단한 것이 구분되어 기록되었는가.
- 안전 모드와 샌드박스를 지켰는가. 허락은 `custom/rules.py`로 정했는가.
- 공개 레포에 시크릿, 개인 정보, 회사 자료가 들어가지 않았는가.

완성도보다 **문제를 어떻게 보고, 무엇을 고르고, 처음에서 얼마나 바꿨는지**를 본다. 다 만들지 못한 것도 계획과 기록으로 설명하면 된다.

## 발표에 담을 것

| 순서 | 내용 |
|---|---|
| 1. 내 업무와 문제 | 어떤 업무인가. Kiro Crew로 맡겨 보며 무엇이 맞지 않았는가(과제물의 근거) |
| 2. 내 플랫폼 | 이름, 한 줄 정의, 뺀 것·바꾼 것·나아지게 한 것 |
| 3. 시연 | 내 업무 자료로 실제로 돌려 본다 |
| 4. 바뀐 것 | `plan` 태그 뒤에 바뀐 것과 그 까닭. 코딩 에이전트와 일하며 내가 판단한 순간 |
| 5. 돌아보기 | 다시 한다면 다르게 할 것, 남은 일 |

## 하지 않을 것

- 안전 모드와 샌드박스 설정을 끄지 않는다. 까닭은 [AGENTS.md](../AGENTS.md)의 "하지 않을 것"에 있다.
- `.homes/`, `.env`를 커밋하지 않는다.
- 남의 레포 코드를 그대로 가져오면 출처와 라이선스를 남긴다.
