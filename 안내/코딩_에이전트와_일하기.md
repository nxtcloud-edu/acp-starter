# 코딩 에이전트와 일하기

이 폴더는 내 코딩 에이전트(Claude Code, Codex, Kiro CLI 가운데 하나)와 함께 고칩니다. 맨 위의 `AGENTS.md`(Claude Code는 `CLAUDE.md`)가 에이전트에게 구조와 지킬 것을 알려 줍니다. 코드를 혼자 다 읽지 않아도 됩니다.

헷갈리지 않게 둘을 나눠 부릅니다.

| 이름 | 어디서 도는가 | 하는 일 |
|---|---|---|
| 코딩 에이전트 | 내 터미널, 이 폴더 | 이 앱의 코드를 읽고 고칩니다 |
| 엔진 | 내 앱이 실행, 작업 폴더 `workspace/` | 앱 안에서 대화하고 일합니다(Claude, Codex, Kiro). 개발 안내는 읽지 않습니다 |

같은 프로그램이 두 자리에 설 수 있습니다. Claude Code는 터미널에서는 코딩 에이전트이고, 앱 안에서는 엔진입니다.

## 열기

이 폴더에서 코딩 에이전트를 엽니다. 앱은 다른 터미널에서 켜 둡니다(`python dashboard.py`).

```sh
claude        # 또는 codex, kiro-cli chat
```

## 이런 말로 시작해 보세요

내 앱으로 만들기. 바뀐 모습이 바로 보이는 것부터 해 봅니다.

```
AGENTS.md를 읽고 이 앱이 무엇인지 짧게 알려 줘.
그다음 앱 이름을 "○○"로 바꾸고, 내가 좋아하는 색감(예: 차분한 초록과 종이색 바탕)으로 꾸며 줘.
```

```
다크 화면도 같은 느낌으로 맞춰 줘. 바꾼 색 토큰을 표로 보여 줘.
```

써 보고 떠오른 것을 더하기.

```
이 앱으로 ○○ 일을 하고 싶어. 대화 말고 어떤 화면이나 기능이 있으면 좋을지 세 가지만 제안해 줘. 아직 만들지 마.
```

```
그중 첫 번째를 만들어 줘. API를 먼저 정하고, 테스트를 쓰고, 화면을 고쳐.
다 되면 python -m unittest discover tests를 돌려서 결과를 보여 줘.
```

모르는 곳은 물어보기.

```
화면에서 질문을 보내면 어떤 파일의 어떤 함수를 거쳐 엔진까지 가는지 순서대로 알려 줘. 고치지는 마.
```

```
만들_곳.md의 "스킬" 줄을 보고, acp-starter 레포의 전체기능-예시 브랜치에서 스킬이 어떻게 만들어졌는지 설명해 줘.
```

## 해 두면 좋은 습관

- 코딩 에이전트가 "다 됐다"고 하면 앱을 새로 고쳐 내 눈으로 봅니다.
- 테스트(`python -m unittest discover tests`)가 통과하는지 봅니다.
- 바뀐 파일을 `git diff`로 훑어봅니다. 모르는 줄은 에이전트에게 설명을 부탁합니다.
- 마음에 들면 커밋합니다. 무엇을 왜 바꿨는지 한 줄 남기면 나중에 돌아보기 쉽습니다.
- 기능은 하나씩 더하고 확인합니다. 한꺼번에 맡기면 무엇이 깨졌는지 찾기 어렵습니다.
- 작업한 날에는 `기록/일지/`에 그날 일지를 남깁니다(`_틀.md`를 복사). 내가 고른 것과 거절한 제안을 적어 둡니다. 에이전트에게 정리를 맡겨도 됩니다.
- 일지까지 쓰면 커밋하고 푸시합니다.

새 기능을 맡길 때 이 한 줄을 붙이면 엔진을 바꿔도 도는 앱이 됩니다.

```
이 기능은 Claude의 CLAUDE.md나 스킬 같은 엔진의 기능 말고 앱 코드로 만들어 줘.
```

## 받지 않는 제안

코딩 에이전트가 제안해도 다음은 받지 않습니다. 까닭은 `AGENTS.md`의 "하지 않을 것"에 있습니다.

- 안전 모드 끄기, Kiro의 `allowedTools` 넓히기, Claude의 `settingSources`나 `SETTINGS` 지우기
- 시크릿을 코드나 문서에 적기. 시크릿은 `.env`에 내가 직접 넣습니다
