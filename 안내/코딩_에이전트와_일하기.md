# 코딩 에이전트와 일하기

이 레포는 내 코딩 에이전트(Kiro CLI, Claude Code, Codex 가운데 하나)와 함께 고친다. 레포 맨 위의 `AGENTS.md`(Claude Code는 `CLAUDE.md`)가 에이전트에게 구조와 지킬 것을 알려 준다.

헷갈리지 않게 세 가지를 나눠 부른다.

| 이름 | 어디서 도는가 | 하는 일 |
|---|---|---|
| 코딩 에이전트 | 내 터미널, 레포 맨 위 폴더 | 이 레포의 코드를 읽고 고친다 |
| 에이전트 | 플랫폼(`custom/agents/`) | 내가 만든 업무 담당. 역할, 스킬, 기본 엔진을 가진다 |
| 엔진 | 대시보드가 실행, 작업 폴더 `workspace/` | 에이전트를 실제로 돌린다(Kiro, Claude, Codex). 개발 안내를 읽지 않는다 |

같은 프로그램이 두 자리에 설 수 있다. 예를 들어 Claude Code는 내 터미널에서는 코딩 에이전트이고, 플랫폼 안에서는 엔진이다.

## 시작하기

레포 맨 위 폴더에서 코딩 에이전트를 연다.

```sh
cd acp-starter
claude        # 또는 kiro-cli chat, codex
```

## 이렇게 맡긴다

처음에는 고치지 말고 설명만 하게 한다.

```
AGENTS.md와 만들_곳.md를 읽고, 이 레포가 무엇을 하는지 설명해 줘.
대시보드에서 질문을 보내면 어떤 파일의 어떤 함수를 거쳐 엔진까지 가는지 순서대로 알려 줘.
아직 아무것도 고치지 마.
```

Kiro Crew 레포에서 찾게 한다. 먼저 옆 폴더에 클론해 둔다(`git clone --depth 1 https://github.com/kirodotdev/KiroCrew.git ../KiroCrew`).

```
../KiroCrew에서 스케줄 결과를 Slack으로 보내는 코드가 어디 있는지 찾아 줘.
이 레포의 custom/deliver.py로 비슷한 일을 하려면 무엇이 필요한지 알려 줘. 코드는 아직 쓰지 마.
```

계획을 세우게 한다. 계획은 내가 고친다.

```
계획/계획서.md의 2절 표를 보고, 항목마다 고칠 파일과 순서를 제안해 줘.
API가 필요한 것은 API의 요청과 응답 모양부터 적어 줘.
```

하나씩 만들게 한다.

```
계획서의 2-2 표 1번 항목만 만들어 줘.
dashboard.py에 API를 먼저 더하고 테스트를 쓴 다음 화면을 고쳐.
다 되면 python -m unittest discover tests를 실행해서 결과를 보여 줘.
```

## 확인하는 습관

- 에이전트가 "다 됐다"고 하면, 대시보드를 다시 켜서 내 눈으로 확인한다.
- 테스트(`python -m unittest discover tests`)가 모두 통과하는지 본다.
- 바뀐 파일을 `git diff`로 읽는다. 모르는 줄이 있으면 에이전트에게 설명을 시킨다.
- 확인한 것만 커밋한다. 커밋 메시지에 무엇을 왜 바꿨는지 쓴다.
- 내가 판단한 것(고른 방법, 거절한 제안)은 `기록/개발일지.md`에 남긴다.

코딩 에이전트에게 "엔진이 바뀌어도 돌게" 만들라고 한 번 더 말해 둔다. `AGENTS.md`의 가장 중요한 규칙이다.

```
이 기능을 Claude의 CLAUDE.md나 스킬 같은 엔진의 기능으로 만들지 말고 플랫폼 코드로 만들어 줘.
다 되면 tests/test_engine_agnostic.py를 포함해 테스트를 모두 돌려 줘.
```

## 맡기지 않는 것

- 안전 모드 끄기, `allowedTools` 넓히기, `settingSources` 지우기. 에이전트가 제안해도 받지 않는다.
- 시크릿을 코드나 문서에 적기. 시크릿은 `.env`에 내가 직접 넣는다.
- 한 번에 여러 기능 만들기. 하나씩 만들고 확인한다.
