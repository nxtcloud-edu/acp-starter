# 자료 요약 HTML 리포트

여러 `.md`·`.csv` 파일을 읽어 핵심을 요약하고, 하나의 HTML 리포트로 만든다.
CSV의 핵심 내용은 표로 담는다.

## 역할 분담

- **AI가 읽고 요약한다.** 각 파일을 읽고 아래 스키마의 JSON을 만든다.
- **Python이 검사하고 조립한다.** `scripts/build_report.py`가 JSON을 검사하고,
  통과하면 HTML로 조립해 저장한다. 문제가 있으면 **저장하지 않고** 알려 준다.

## 요약 규칙

- **맨 위 TL;DR 불렛 3개를 가장 먼저 쓴다.** 리포트 최상단에 TL;DR 상자로 표시된다.
  보고서 전체 핵심을 3개 불렛으로 요약한다(정확히 3개여야 하며, 많거나 적으면 검사에서 걸러진다).
- **자료에 없는 내용은 넣지 않는다.** 원문에 근거한 것만 요약한다.
- **애매한 값은 `"확인 필요"`로 남긴다.** 추측하지 않는다.
  (생성일을 모를 때는 `null`로 두면 리포트에 "확인 필요"로 표시된다.)
- CSV는 핵심 열만 골라 표로 옮긴다. 각 행의 칸 수는 열 수와 반드시 같게 한다.

## 요약 JSON 스키마 (고정)

```json
{
  "제목": "리포트 제목",
  "생성일": "YYYY-MM-DD 또는 null",
  "TL;DR": ["핵심 요약 불렛1", "핵심 요약 불렛2", "핵심 요약 불렛3"],
  "문서 요약 목록": [
    { "파일": "a.md", "요약": ["요점1", "요점2"] }
  ],
  "표 목록": [
    {
      "제목": "표 제목",
      "출처": "b.csv",
      "열": ["열1", "열2"],
      "행": [["값1", "값2"], ["값3", "값4"]]
    }
  ]
}
```

- 최상위 항목은 `제목`, `생성일`, `TL;DR`, `문서 요약 목록`, `표 목록` 다섯 개로 고정. 빼거나 더하지 않는다.
- `TL;DR`: 문자열 **정확히 3개**로 된 목록. 리포트 최상단에 TL;DR 상자로 가장 먼저 표시된다. 3개가 아니면 검사에서 걸러진다.
- `문서 요약 목록` 원소: `파일`(문자열), `요약`(문자열 목록). 빈 요약은 `[]`.
- `표 목록` 원소: `제목`·`출처`(문자열), `열`(문자열 목록), `행`(문자열 목록의 목록).
- **표의 각 행 칸 수 == 열 수.** 다르면 검사에서 걸러진다.

## 실행 절차

경로는 모두 작업 폴더(`workspace/`) 기준이다.

1. **AI가 파일들을 읽고** 위 스키마의 요약 JSON을 만든다.
2. **Python으로 검사·조립한다.** 요약 JSON을 표준 입력으로 `scripts/build_report.py`에 넘긴다.
   JSON을 파일로 먼저 쓰지 않는다. 명령 한 번으로 검사와 저장을 끝낸다. 리포트는 `outbox/`에 저장한다.

```bash
python3 skills/data-to-html/scripts/build_report.py --out outbox/리포트.html <<'JSON'
{"제목": "...", "생성일": null, "TL;DR": ["...", "...", "..."], "문서 요약 목록": [], "표 목록": []}
JSON

# 저장 전 검사만
python3 skills/data-to-html/scripts/build_report.py --check-only <<'JSON'
{ ... }
JSON
```

- 종료 코드 `0`=검사 통과(저장/검사만), `1`=검사 실패(저장 안 함), `2`=입력 오류.
- 검사 실패 시 걸러지는 경우: 항목 누락·추가, 자료형 오류, **표의 열 수와 행의 칸 수 불일치**.
- 실패하면 출력된 오류를 사용자에게 그대로 전하고, 요약 JSON을 고쳐 재실행한다.
- 명령을 실행하기 전에 플랫폼이 사용자에게 허락을 물을 수 있다. 거절되면 요약을 답에 보여 주고 끝낸다.

스크립트 위치: `skills/data-to-html/scripts/build_report.py`
